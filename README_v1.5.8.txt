Hangcha Sales Assistant v1.5.8 — PDF客户名称优先识别
===================================================
基于 v1.5.7，保留原有扫描、金额判断、Excel写入前确认、归档和Teams拖拽功能。

1. 订单 PDF 识别
   - 先根据已验证的 Hangcha Salesorder 版式，在左侧客户地址块提取客户正式名称。
   - 自动清理重叠/重复文字（如 PPaassssmmaannnn），并要求识别到可信的地址证据。
   - 若版式不匹配或客户无法可靠定位，回退为原有“客户文件夹/文件名前缀”判断；不猜测。
   - 若依然无法确定客户，记录待复核，不自动写入 Excel。

2. 发票和发货单关联
   - 完整扫描后，仅按明确的杭叉内部合同号（Order No. / Ordernumber）关联订单。
   - 若同合同已识别到唯一可信订单客户，关联发票及发货单使用该正式名称。
   - 发票先被扫描也没有关系：扫描完成后统一关联。
   - 若同合同出现多个不同订单正式客户名，关联记录标记待复核，不自动写入。
   - 不从 Customer No.、客户自己的采购订单号或发货单号码推导合同号。

3. 显示与 Excel
   - 内部业务字段 customer 存客户正式名称。
   - GUI 只在文件夹简称与正式名称开头一致时显示简称（例如 Kloz）；否则显示正式名称。
   - 选中 PDF 或合同后，在“记录说明”可查看完整客户名称和来源。
   - 新增 Excel 行使用正式名称，已有 Excel 行绝不因客户名称变化而被覆盖。
   - 从 Excel 读取的订单备注、金额和日期逻辑完全不变。
   - 新的 CSV 导出新增 customer_source 与 customer_alias 两列，便于核对来源。

真实验证样本：
   订单 266716 -> Passmann Gabelstapler
   订单 266686 -> KLOZ Gabelstapler GmbH
   Passmann 发票 H20263319 -> 通过合同 266716 关联 Passmann Gabelstapler

升级（从 v1.5.7）：
   1. 完全关闭 GUI，备份安装目录及本地数据库。
   2. 解压本次升级补丁，将其中 .py 文件复制到软件目录并覆盖同名文件。
   3. 添加新模块 gui_customer.py；保留已有 state、.venv、用户配置和 SQLite 数据库。
   4. 运行 10_START_GUI.bat，执行一次完整扫描。
   5. 首次写入 Excel 前照常执行“核对业务 / 预览 Excel”并人工确认。

首次安装：可使用 v1.5.8 完整 Windows 压缩包，双击 01_INSTALL.bat。

测试：13 项新功能专项测试通过；已用虚拟显示器验证 Tkinter GUI 能启动。
真实 Windows、不同地区/版式的历史订单仍需在用户电脑上验证。
不需要迁移或重置任何 SQLite 数据库；不对原 PDF 或 Excel 做后台写入。
