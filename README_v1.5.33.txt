HCE Oracle v1.5.33 | 订单 / 发票 / 发货单完整归档修复
=========================================================

【主要修复】
1. 合同下存在订单及发票 PDF 时，归档时自动将合同号明确一致、状态可靠的发货单 PDF 纳入同一归档组。
   识别合同号只使用 PDF 正文唯一的 Ordernumber，不以 Delivery No.、客户名、目录或文件名推断。
2. 一次归档成功后，订单、发票和这些关联发货单均从「识别结果」和「未匹配文件」中消失；
   在「归档管理」中能够查看并一组恢复。原始 PDF 不移动、不删除。
3. 历史遗留场景：若同一合同的订单＋发票已经被旧版归档，但发货单还在「未匹配文件」，
   重新扫描后在「未匹配文件」中选中该发货单，右键「归档此 PDF（需确认）」或勾选批量归档；
   程序仅在找到唯一匹配的历史订单＋发票归档组时允许补归档，并使用原归档组 ID。
   不会无提示自动迁移旧记录。补归档完成后可以和原合同一起恢复。
4. 待开票订单（无发票）在原有的二次确认后，会一起归档明确关联的发货单；
   单独归档已复核文件、作废文件、贷项通知单的规则不变。
5. 不可靠的发货单不会被自动关联：正文没有唯一 Ordernumber、多个 Ordernumber、
   或文件处于待复核但未人工复核，都不会被猜测归档。
   已能确定同一合同但仍待复核的发货单，将暂停整组归档并给出提示。
6. 识别结果下拉菜单不再显示「已归档」和「已开票（归档）」的筛选选项；
   切到「归档管理」时提供归档类型、补归档发货单及文件类型筛选。
   极少数旧数据可能仍在未归档合同的状态文字中显示「已开票（归档）」，这是历史发票已归档的提示，而非筛选选项。

【升级方式：从 v1.5.32】
1. 完全退出 HCE Oracle，备份程序文件夹。建议同时备份本地归档数据库：
   %LOCALAPPDATA%\HangchaSalesAssistant\archive_state.sqlite3
2. 将 HCE_Oracle_v1.5.33_Archive_Delivery_Patch.zip 解压至程序目录，覆盖同名文件。
3. 运行桌面 HCE Oracle 快捷方式或 10_START_GUI.bat。无需重新安装 Python。
4. 执行一次完整扫描，对相关订单使用「归档此 PDF」前预览全部受影响文件。
5. 对历史遗留的单独发货单，参照第 3 条手动补归档。

【限制与数据安全】
- 软件不修改原始 PDF、订单/库存 Excel；归档只写入当前员工的 SQLite 归档及审计记录。
- 归档文件不再进入普通 Excel 新增写入候选。请在归档前确认相关业务数据已经登记。
- 与合同号不明的发货单不能保证自动归档，需人工核查后自行决定。
- 程序层通过 12 项归档、合同、恢复、旧记录补归档测试；实际 Windows 图形界面仍需现场验证。
- 此次没有更改数据库结构，无需迁移历史归档记录。
