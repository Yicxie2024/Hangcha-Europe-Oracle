HCE Oracle v1.5.34 | 发货单历史归档关联 + 快速增量扫描
================================================================

【新增与修复】
1. “识别结果”和“归档管理”中编号列统一为“订单/发货/发票号”。
   订单 PDF 显示订单号 Order No.；发货单显示其自身的 Delivery No.；发票显示 Invoice No.。
   如果不能从对应 PDF 识别该单据自身编号，显示“—”，不会偷用合同号来冒充发货单号/发票号。
2. 发货单合同关系只读取 PDF 正文中明确且唯一的 Ordernumber；与活跃订单匹配时仍正常附属合同树。
   若合同订单已经归档，且能唯一关联历史归档组，则识别结果中显示独立的
   “历史发货单待补归档”分组，而不是笼统地留在“未匹配文件”。
3. 「其他功能」→「检查历史发货单归档关联（需确认）…」：
   - 完整扫描后可使用。按 PDF 正文 Ordernumber 查找唯一的已归档订单组，支持
     原本订单+发票共同归档的合同，也支持过去明确“待开票归档”的订单。
   - 显示可补归档清单和无法唯一匹配、需复核、仍有活动订单的文件，要求人工预览确认。
   - 确认后在单个 SQLite 事务中补归档，加入原归档组，恢复订单组时一起恢复发货单。
   - “撤销上次归档”只撤销本次新增的文件；“归档管理→恢复合同”才恢复整组原订单/发票/发货单。
   - 未识别唯一 Ordernumber、多个历史合同组、未复核等情况不会自动归档。
   - 不会自行批量归档既有 52 份“未匹配”文件；只有确认过的可靠匹配记录会处理。
4. 默认“快速增量扫描”：每次遍历配置目录并检查路径、大小、修改时间和文件状态。
   - 已归档且未变化的 PDF 跳过正文解析；普通未归档且未变化的 PDF 从本地 SQLite 缓存恢复原始识别结果。
   - 新增、更改的 PDF 重新解析。缓存按员工档案隔离，PDF 解析规则升级时会自动失效。
   - 开票状态和合同关系会在每次完整扫描后重新计算，避免旧缓存固定“待开票”。
   - 已归档发货单的 Delivery No. 在首次建立识别缓存后，也能于下次打开归档管理时直接显示，
     不用重新解析 PDF；升级前没有缓存的旧归档记录需要扫描一次才能取得这个字段。
   - 归档/恢复及 Excel 写入前仍独立重新校验真实 PDF 的 SHA-256，缓存不授予操作权限。
5. 「其他功能」→「扫描模式」：
   - 快速增量扫描（默认）。
   - 重新识别未归档 PDF（不重新解析未变化的归档 PDF）。
   - 完整归档核验（SHA-256）——对归档文件核验真实内容，发现被替换的文件不继承旧归档状态。
   - 在菜单里选定模式后，点击主界面的“开始扫描（只读）”执行。
6. 扫描状态栏显示：缓存复用、已归档跳过正文解析、真正解析的 PDF 数量、归档校验数量、需核验的归档文件数量。

【升级】
1. 先退出 HCE Oracle。备份整个程序目录，并建议备份：
   %LOCALAPPDATA%\HangchaSalesAssistant\archive_state.sqlite3
   %LOCALAPPDATA%\HangchaSalesAssistant\gui_config.json
2. 将 v1.5.34 增量补丁解压覆盖到 v1.5.33 的安装目录，不要删除原有程序目录。
3. 双击桌面 HCE Oracle 快捷方式或 10_START_GUI.bat。
4. 完成一次快速增量扫描（首次建立缓存可能需要重新解析已有文件）。
5. 需处理旧版遗留发货单时，使用「其他功能」→「检查历史发货单归档关联（需确认）…」。
   先检查可补充清单，再手动确认写入归档。

【数据安全与边界】
- 新缓存：%LOCALAPPDATA%\HangchaSalesAssistant\scan_cache.sqlite3
  可删除缓存数据库重新扫描；它不是归档记录数据库，删除它不会解除归档。
- 既有 archive_state.sqlite3、remark_drafts.sqlite3、gui_config.json 和原始 PDF / Excel 不会被安装包清除或重置。
- 增量检查文件元数据不等于逐文件做 SHA-256；如怀疑有人替换原 PDF，应选择“完整归档核验”。
- 完整扫描仍遍历全部源目录；网络磁盘、极大量小文件时仍有目录枚举耗时。
- Excel 业务核对和真正写入仍会读取并核验相关 PDF，速度不等于单纯扫描阶段的缓存速度。
- 本版本没有改变“归档前请先确认 Excel 登记完毕”的业务风险。
- Windows GUI 和业务现场需要以员工电脑上的真实 PDF / Teams 路径进一步确认。

【验证】
- 10 项自动化回归测试（缓存、变更失效、不同员工隔离、归档、恢复、待开票重算、历史补归档）。
- 使用实际订单和发票 PDF 验证：首遍真实解析、第二遍 100% 缓存复用。
- 使用 Linux Xvfb + Tkinter 完成软件两次扫描和历史发货单补归档界面测试。
- 原 ZIP 包内所有历史模块与 README 保持，不修改旧 SQLite 归档 schema。
