Hangcha Sales Assistant v1.5.10 — 业务信息仅从 PDF 正文获取
========================================================

重要变化
1. 客户名称、订单/发票类型、内部合同号、发票号、日期、净额、含税金额必须来自 PDF 文字或经 PDF 内合同号关联的另一份 PDF；不再从文件名或客户文件夹推断。
2. 识别结果「客户」列始终显示从 PDF 提取的完整正式名称，不再采用文件名前缀简称。因此 266457 与 266873 都显示 Siemers Transporttechnik GmbH。
3. 订单：仅识别 PDF 左侧客户地址块，不采用收货地址。发票：可独立从发票 PDF 的客户地址块提取客户名称；识别失败时尝试通过 PDF 内 Ordernumber 与已识别订单关联。
4. 如果没有可靠 PDF 证据，客户显示「未确定」，文件状态「待复核」，禁止自动写入 Excel。来源目录和配置中的类型提示不再覆盖 PDF 类型判定。
5. 若同一合同关联的多个 PDF 具有不一致的客户正式名称，则整组进入「待复核」，不自动选择其一。
6. 月末检查也不再从文件名补合同号。无法关联的发票会进入待核提示，不推断缺票。

保留两项用户专门定义的文件名操作标记
- 「作废」：完全忽略、不解析、不计业务异常，但可以单独归档；不会从作废文件名提取任何客户、合同或类型信息。
- 「有误」：发票正常解析，但原有跨文件/Excel 金额比对豁免仍有效。其他检查仍执行。
这两个词仅用于工作流标记，不是业务字段的来源。

兼容与安全
- 旧 Excel 的客户名称不被自动改写；新记录使用 PDF 正式名称。
- 原归档数据库、上传历史、个人配置、备注和 Teams 拖拽逻辑保留。
- 保留原来的核对预览与写入二次确认，不自动修改任何 Excel 或 PDF。
- 较早或其他模板 PDF 可能因此显示「待复核」，这是有意的防误识别行为。

升级
1. 关闭 GUI，备份整个原程序目录及 %LOCALAPPDATA%\\HangchaSalesAssistant。
2. 用补丁的 automation.py、gui.py、gui_scanner.py、gui_customer.py、gui_archive.py 覆盖原目录同名文件。
3. 不要删除旧 .venv、state、config.json、SQLite 数据库或业务 PDF/Excel。
4. 启动 10_START_GUI.bat，重新完整扫描，并核对待复核数量及客户名称。

实际样本验证：Siemers（两份）、BUW、Passmann、KLOZ 订单；Passmann、Diez 发票。
本版的 Linux/Xvfb 与本地 PDF 模拟测试已通过；Windows + Excel + Teams 仍需本机验收。
