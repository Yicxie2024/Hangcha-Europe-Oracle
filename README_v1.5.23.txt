Hangcha Sales Assistant v1.5.23 — 统一拣货单库位定位
===================================================
目标：保留 v1.5.22 的真实仓库走廊寻路；优化“候选位置”与缺失细分编码的处理。

库位识别与分层
------------
- 前5个字符可定位：A0103 = A列01行，货架层03，一楼。前5字符由 A–P、01–12、01–12 组成。
- 01–04 / 05–08 / 09–12 表示物理1/2/3楼的4级货架高度；编号越大相对越高。
- A0103I、A010203 以及其他含有完整合法前5位的位置，直接按前5位归层；可疑尾码加注释，不因此丢失路径。
- A01、A010 等只有可识别列/行、缺少完整层号：默认一楼末尾，注明“层号未知、现场核查”。
- 例如 P1405 能从第4-5位确定属于二楼，但行14超出平面12行，则列在二楼末尾，不作虚假路径。
- G/H列行01–06是楼梯区域；可能有录入异常，放对应楼层末尾标记核查，不规划穿过楼梯区的货架路线。
- 没有合理楼层信息或其他格式（如 Y0101）进入“无法确认区域”。其表格与正常拣货行完全相同。

多库位与数量
----------
- 一个库存行中有多个库位，例如 N1007/N0907/P0509/P051002，全部按各自物理楼层列出。
- 有效库位仍参与当层路线规划，不因有多个库位而被挪到另一张候选表。
- 库存 Excel 只有该行合计量，不能把该数量复制到每个库位。拣货单在第一条位置仅显示“待分配N”，其他位置标记“同一需求”，由现场核对实际分配数量；“库存”显示“整行合计”，备注列提示来源总库存。
- 已明确为单独库存行、单个有效库位的配件可以自动分配数量；其余只作可视化推荐路线，不能凭打印自动完成出库。
- 本版所有区域使用相同表头：序号 / Rack No. / ERP No. / Part No. / 描述 / 应拣 / 库存 / 实拣 / 确认 / 备注。

路线和安全
----------
- 各层 G/H 06–07 横向通道连接楼梯。每层3F→2F→1F，通道距离是启发式估计，非测量距离或严格最优。
- 同一平面位置按货架高度由高到低，再看货架格和后缀。
- 对定位不完整的库位只确定楼层，不虚构行走距离或可取数量。
- 本次修改 gui_picking_core.py、gui_picking_pdf.py、gui_picking_ui.py 和 gui.py（显示版本号）。
- 原始库存 Excel 和订单 PDF 只读；真实 Windows 打印及实物货架需现场验证。
