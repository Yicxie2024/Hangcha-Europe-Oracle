Hangcha Sales Assistant v1.5.11 — 订单 PDF 客户名称优先
========================================================

规则
- 对于订单 PDF 与关联发票 PDF 的客户名称不同：同一内部合同号（订单 Order No. / 发票 Ordernumber）对应的订单 PDF 客户名称是最终依据。
- 发票在识别结果、Teams 上传列表和新写入 Excel 发货子表中统一使用订单客户名称。
- 客户名称不一致本身不再触发“待复核”或阻止 Excel 新增；在识别结果的发票备注/详情里保留原发票客户名和订单客户名作核对提示。
- 如果没有能可靠提取客户名称的订单，使用发票 PDF 自身提取的客户名称。若没有订单可参考、多个发票名称相互矛盾，则继续待复核。
- 同一合同下多个订单 PDF 如果提取到不同客户名称，继续待复核，不能随意指定一个。
- 如果 PDF 还有其他问题（金额为 0、字段缺失等），仍保持其原有待复核状态。
- 业务字段仍只来源于 PDF 内容，不使用文件名/文件夹名称推断；仅保留“作废”和“有误”文件名工作流标记。
- 已有 Excel 里的客户名称不自动修改，避免覆盖人工维护的数据；新记录使用统一后的订单客户名。
- 不变更 SQLite 归档、Teams 上传历史、备注或 Excel 写入确认机制。

从 v1.5.10 升级
1. 关闭软件，并备份 C:\Hangcha Assistant 及 %LOCALAPPDATA%\HangchaSalesAssistant。
2. 使用补丁中 gui_scanner.py、automation.py、gui.py 覆盖同名文件。
3. 保留现有 state、config.json、.venv、归档和上传历史 SQLite 文件。
4. 运行 10_START_GUI.bat，重新完成一次扫描。若之前存在仅因客户名称差异而待复核的发票，新的扫描将重新按本规则识别。

验证
- 13 项新规则测试通过，包含真实 PDF 的模拟发票客户差异、扫描顺序、Excel 预览输入和上传候选。
- 19 项上一版本 PDF 内容识别回归测试通过（对客户名称冲突的预期按新规则更新）。
- 测试在本地环境完成；Windows Excel COM 和 Teams 实际操作仍需在用户电脑验收。
