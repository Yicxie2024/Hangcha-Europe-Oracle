Hangcha Sales Assistant v1.5.6 — Teams「已上传」标签页修复
============================================================
从 v1.5.5 升级：先退出 GUI，备份程序目录与 SQLite 数据库，然后覆盖：
  teams_graph.py
  gui_teams.py
无需重新安装 Python。完整安装包另行提供。

问题原因：v1.5.5 的 invoice_candidates() 在加载时提前跳过 SQLite 已上传的
PDF，导致刷新/重新打开上传窗口后「已上传」标签页为空、统计计数为 0。

修复内容：
1. 已上传发票保留在本次扫描的候选数据中，由 GUI 状态区分「待上传」「已上传」。
2. 上传完成并点击「已在 Teams 核实 → 标记完成」后，立即显示已上传状态；
   刷新或重新打开窗口后仍可看到（须原 PDF 仍在本次扫描范围内）。
3. 两份本地 PDF 具有同样合同号和发票号时，已确认上传的文件仍显示「已上传」，
   未确认的重复文件则保持「需复核」，不允许直接重复上传。
4. 调整状态栏文案，准确区分待上传、已上传、需核对。

注意：
- 拖拽到 Teams 本身不会自动完成 SQLite 登记。须核实云端上传完成后按
  「已在 Teams 核实 → 标记完成」。
- 「已上传」筛选显示本次扫描中还能识别到的 PDF，不是完整历史数据库视图。
  已移动或已删除的文件仍可在独立「上传历史」窗口查看历史记录。
- 更改员工配置(profile)、移动或重命名 PDF，会影响当前基于文件路径和指纹的
  已上传匹配；本补丁不改变原有判重规则或自动云端检查能力。
- 不修改已有 SQLite 数据库、PDF、Excel 或归档记录。
