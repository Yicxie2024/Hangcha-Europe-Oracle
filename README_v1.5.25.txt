Hangcha Sales Assistant v1.5.25 — 多库位独立库存 / 配件种类序号
==========================================================

在 v1.5.24 上的增量修改；保留三层连续拣货单自动分页、楼层路线、PDF 识别、库存搜索、月度发运统计和 Teams 功能。

改进 1：每一种配件仅计算一个拣货序号
------------------------------------
- 拣货单的“#”表示唯一配件种类，不是库位行数。
- 一个 ERP/Part 对应不同楼层、多个库位时，这些位置显示相同的编号（例如都显示“2”），配件种类总数只计算一次。
- 所有库位仍然按 3F→2F→1F 的实际路径排序，不会为了合并配件而改变路线。

改进 2：显示每个库位的独立库存，而不是总库存
------------------------------------------
- 若原库存 Excel 的一条记录只有一个库位，该行 MA（存）可直接作为该库位的库存。
- 若同一记录有多个库位，但 Excel 只提供 MA 总库存，则不能推断各库位数量：PDF 的每个库位在“库存”列显示“待核”，不再显示“整行合计”，也不把总库存复制给所有库位。
- “应拣”仍是该配件唯一需求总量；数量待分配时只在第一位置展示需求，其他位置展示“同一需求”，防止重复拣取。

改进 3：在界面里核对多库位库存
--------------------------------
1. 打开「统一库存搜索与拣货单」，导入或输入配件，点击「查询库存」。
2. 在下方按钮栏点击「核对多库位库存…」。
3. 双击各库位，输入真实库存量；留空表示未知/尚未盘点。
4. 全部库位均已填写时，必须与对应 Excel 行 MA 总库存相等才能保存；若仅补部分库位，已知数量之和不得超过 MA。
5. 保存后预览或打印，已确认的库位显示对应数值，尚未知的继续显示“待核”。

重要的数据安全规则
------------------
- 完全不修改原始库存 Excel，不进行库存扣减或自动预留。
- 手动核实数据保存在本机 LOCALAPPDATA/HangchaSalesAssistant/picking_rack_stock.json。
- 文件绑定源库存 Excel 的路径、修改时间、大小和内容哈希；库存文件发生变化后不继续套用旧的库位分配结果，需要重新核对。
- 若在其他员工的电脑上打印，须在该电脑单独核对，因为本机补录文件并未同步到局域网。
- 这些补录数值是用户人工确认的业务数据，不是程序自动从 Excel 推导得到的独立库位库存。

安装
----
升级 v1.5.24：关闭软件，备份原程序文件夹，将增量补丁解压覆盖同名文件后运行 10_START_GUI.bat。
其他版本：使用完整 Windows 包；初装运行 01_INSTALL.bat，之后运行 10_START_GUI.bat。
不需要删除归档数据库、用户设置、订单 PDF 或已有 Excel。
