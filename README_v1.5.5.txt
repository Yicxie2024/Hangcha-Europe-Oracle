Hangcha Sales Assistant v1.5.5 — 原始 PDF 丢失保护与独立清理
================================================================
从 v1.5.4 升级：退出 GUI，备份程序目录，然后覆盖以下 3 个文件：
  gui.py
  gui_archive.py
  gui_archive_tree.py
不用重新安装 Python；原有归档状态、待写备注和 Excel 不需要迁移。

新增保护：
1. 已归档 PDF 丢失、被移动、或原位置变成不同内容：归档历史仍保存在员工
   本地 SQLite 数据库，归档管理保持可见。
2. 在归档管理中具体文件行右键，选择「重新定位原始 PDF…」：
   选择现存 PDF，程序验证 SHA-256 指纹必须与归档时完全一致；确认后才更新
   归档数据库中的文件路径，保留合同分组、归档时间及记录。不会复制、删除 PDF。
3. 归档组恢复、右键恢复、批量恢复、撤销上次归档都由数据库层检查整组的每个
   原始 PDF。任意 PDF 丢失或指纹变化：阻止整个归档组恢复，保持所有归档状态。
4. 在归档管理中选中失效 PDF 的子行，右键「单独清除失效归档记录…」。
   先显示具体文件和风险，再要求输入「清除」完成最终确认。
   此操作只清除选中的一条无效归档数据库记录，不自动展开整个合同组，也不删
   除源 PDF/Excel。完整记录内容保留于 SQLite 的 audit 审计表，供后续追查。
   原始 PDF 仍有效且哈希一致时，程序在数据库层强制拒绝清除。
5. 归档管理中对源文件缺失的条目显示「源文件缺失」并在详情区解释操作。

重要事项：
- 「清除失效归档记录」不是恢复 PDF；已经从磁盘删除的 PDF 需要你从备份等
  途径自行找回，或使用完全相同的副本重新定位。
- 如果某合同的发票记录被清理但 Excel 中没有对应发货记录，重新扫描和核对后
  该合同可能显示「待开票」。所以清理前应先核对业务资料。
- 本补丁未修改 PDF 解析、日期和 VAT 规则、Excel 写入、Teams 拖拽上传等功能。
- 需要完成一次来源目录扫描后，再在归档管理中使用归档状态操作。
- 应将原有 archive_state.sqlite3 一同备份。默认位于 Windows 用户本地应用
  数据目录的 HangchaSalesAssistant 文件夹中，而不是程序安装目录。

测试：在隔离测试环境中运行 123 项自动测试，包含本版新安全场景、真实 Tk
组件交互和原有业务规则回归。真实 Windows 11 与 OneDrive/Excel 环境仍需要
用户本机使用测试副本确认。
